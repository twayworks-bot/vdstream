## 2. 결함 원인 분석 (Root Cause Analysis)

### 2.1 결함 발생 메커니즘
1. **Windows 플랫폼 기본 인코딩 충돌**:
   - Windows 한국어 로케일 환경에서 Python 표준 라이브러리 `subprocess.run(..., text=True)` 호출 시, `encoding` 인자를 명시하지 않으면 시스템 기본 인코딩(`locale.getpreferredencoding()`)인 `cp949`(ANSI)가 적용된다.
2. **FFmpeg / x264 출력 스트림의 UTF-8 / 바이너리 문자열**:
   - FFmpeg 실행 및 x264 인코딩 시 출력되는 stderr/stdout 로그에는 저작권 기호(`©`, Latin-1 0xA9 또는 UTF-8 시퀀스), 다국어 메타데이터 등이 포함된다.
3. **`_readerthread` 비동기 파이프 리더 크래시**:
   - `subprocess.run(capture_output=True)` 내부에서 백그라운드로 구동되는 `_readerthread` 스레드가 스트림 바이트를 `cp949`로 디코딩하려 시도하다가 `0xa9` 바이트에서 `UnicodeDecodeError` 예외를 발생시키고 스레드가 비정상 종료된다.

### 2.2 영향 범위
- `app/services/ffmpeg_service.py`:
  - `probe_video` (Line 80): `ffprobe` 실행 시 `subprocess.run(..., text=True, check=True)` -> encoding 미지정
  - `transcode_to_720p_and_hls` (Line 237): MP4 변환 시 `subprocess.run(mp4_cmd, text=True)` -> encoding 미지정
  - `transcode_to_720p_and_hls` (Line 264): HLS 변환 시 `subprocess.run(hls_cmd, text=True)` -> encoding 미지정

## 3. 해결 계획 (Fix Plan)

1. **`app/services/ffmpeg_service.py` 인코딩 및 에러 핸들러 통일**:
   - 모든 `subprocess.run` 호출에 `encoding="utf-8"`, `errors="replace"` (또는 `"ignore"`)를 명시하여 어떤 비표준 바이트나 다국어 문자가 들어오더라도 디코딩 예외 없이 안전하게 읽어오도록 개선.
2. **안전한 프로세스 래퍼 도입 또는 subprocess 호출 강화**:
   - 필요 시 `errors="replace"`로 유실 없이 대체 문자로 안전하게 수신하도록 방어.
3. **단위 테스트 추가 (`tests/test_ffmpeg_encoding.py`)**:
   - UTF-8 및 특수 바이트가 포함된 출력 환경에서도 `ffmpeg_service`가 `UnicodeDecodeError` 없이 정상 작동함을 검증.
4. **산출물 및 문서 업데이트**:
