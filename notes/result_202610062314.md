## 1. 결함 개요 및 증상

- **요청 URL**: `http://localhost:5000/api/v1/streams/vid_20261006230843_66bae763/mp4`
- **발생 오류**: `HTTP 404 Not Found: {"detail":"Segment file not found."}`
- **원인**:
  - `app/api/v1/streams.py`의 라우트 등록 순서상, 와일드카드 세그먼트 핸들러 `/{video_id}/{segment_name:path}`가 고정 경로인 `/{video_id}/mp4`보다 상단에 정의되어 있었습니다.
  - 이로 인해 FastAPI(Starlette) 라우팅 엔진이 `/mp4` 요청을 `segment_name = "mp4"`로 파싱하여 HLS 디렉토리에서 `mp4`라는 이름의 세그먼트 파일을 찾으려 시도하였고, 해당 파일이 존재하지 않아 `Segment file not found` 404 에러가 반환되었습니다.

## 2. 결함 수정 및 개선 내역 (Code Changes)

### 2.1 라우터 순서 재배치 및 오인식 방어벽 추가 ([`app/api/v1/streams.py`](file:///C:/Dev/python/vdstream/app/api/v1/streams.py))
1. `@router.get("/{video_id}/mp4")`를 와일드카드 경로보다 상단으로 이동하여 `/mp4` 요청이 무조건 MP4 Range 스트리밍 핸들러로 먼저 매칭되도록 보장하였습니다.
2. 와일드카드 세그먼트 핸들러 `@router.get("/{video_id}/{segment_name:path}")` 내부에도 방어 로직을 추가하여, 혹시라도 `segment_name == "mp4"` 또는 `segment_name == "master.m3u8"`이 유입될 경우 각각 `stream_mp4_range`와 `get_hls_master_playlist`로 즉시 위임 처리하도록 이중 보호망을 구축하였습니다.

### 2.2 실제 FFmpeg 7.1 바이너리 탑재 및 FFprobe 부재 대응 ([`app/services/ffmpeg_service.py`](file:///C:/Dev/python/vdstream/app/services/ffmpeg_service.py))
1. `./bin/ffmpeg.exe`에 정적 빌드된 최신 FFmpeg 7.1 바이너리를 배치하였습니다.
2. `ffprobe`가 없는 환경에서도 `ffmpeg -i <input>` 명령어의 표준 에러 스트림을 정밀 정규식으로 파싱하여 재생 시간(Duration), 가로/세로 해상도, 비디오/오디오 코덱, 비트레이트를 온전히 추출하도록 `probe_video` 로직을 대폭 강화하였습니다.
3. 이에 따라 실제 비디오에 대한 720p H.264 MP4 및 HLS 번들링이 실제로 수행됩니다.
