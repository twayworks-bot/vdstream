## 2. 원인 분석 및 기술적 진단 (Root Cause Analysis)

1. **라우팅 패턴 충돌 (Route Shadowing Bug)**:
   - `app/api/v1/streams.py`에 정의된 라우터 순서:
     ```python
     @router.get("/{video_id}/master.m3u8")
     async def get_hls_master_playlist(...)

     @router.get("/{video_id}/{segment_name:path}")
     async def get_hls_segment(...)

     @router.get("/{video_id}/mp4")
     async def stream_mp4_range(...)
     ```
   - FastAPI / Starlette 라우팅 매칭 메커니즘은 등록된 순서대로 정규식 패턴을 탐색함.
   - 요청 URL `/api/v1/streams/{video_id}/mp4`에 대해, 와일드카드 경로 파라미터를 갖는 `/{video_id}/{segment_name:path}`가 `/{video_id}/mp4`보다 먼저 정의되어 있어서, `segment_name = "mp4"`로 캡처됨.
   - 이에 따라 `get_hls_segment` 핸들러가 실행되어 HLS 디렉토리 내 `mp4`라는 이름의 세그먼트 파일을 찾게 되고, 해당 파일이 존재하지 않으므로 `HTTP 404: {"detail":"Segment file not found."}` 오류가 반환됨.

2. **FFmpeg 실행 환경 진단**:
   - 상태값에서 `file_size_bytes: 1066`은 시스템에 FFmpeg 바이너리가 없을 때 생성된 Fallback/Mock MP4 파일 헤더 크기임.
   - 실제 비디오 `"C:\Users\gluemii\Videos\5마을.찬양제.mp4"`가 존재하지만 호스트 머신에 FFmpeg 바이너리가 배치되지 않아 Mock 모드로 동작함.
   - 바이너리 배치 가이드 및 환경 점검도 함께 제공 필요.

## 3. 해결 계획 (Resolution Plan)

1. **라우팅 정의 순서 재배치 및 경로 분리**:
   - `/{video_id}/mp4` 및 `/{video_id}/master.m3u8` 고정 경로를 와일드카드 경로보다 반드시 **앞에 배치**.
   - 와일드카드 라우트는 고정 라우트들이 일치하지 않는 경우에만 실행되도록 하거나, 세그먼트 전용 엔드포인트(`/{video_id}/segment/{segment_name:path}`) 및 하위 호환 와일드카드를 안전하게 처리.
2. **테스트 케이스 추가**:
   - `/api/v1/streams/{video_id}/mp4` 호출 시 `Segment file not found`가 아닌 정상 MP4 스트림(HTTP 200 또는 206)으로 응답함을 검증하는 테스트 추가.
3. **누적 요구사항 및 변경 이력 기록**:
   - `notes/requirement.md`에 라우팅 우선순위 및 MP4/HLS 스트리밍 엔드포인트 충돌 방지 요건 누적.
   - `notes/history.md`에 결함 수정 이력 작성.
   - `notes/result_202610062314.md`에 수정 결과 및 검증 테스트 보고서 기록.
