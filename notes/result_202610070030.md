## 1. 결함 분석 및 구현 개요

### 1.1 결함 원인
1. **대시보드 폴링 조기 중단**:
   `dashboard.js`의 기존 폴링 로직은 시스템 지표인 `active_transcoding_count > 0 || queued_count > 0`일 때만 비디오 테이블을 폴링했습니다. 따라서 트랜스코딩 작업이 완료되어 카운트가 `0`으로 내려가는 순간 폴링이 완전히 멈추어, 화면상의 행이 이전 상태인 `변환 중...`에 영구적으로 고정되어 있었습니다.
2. **진행률(%) 지표 부재**:
   `Video` 모델과 REST API 응답에 진행률(`progress_percent`) 필드가 존재하지 않아 클라이언트 및 외부 웹앱에서 변환 진행 정도를 0~100%로 추정할 수 없었습니다.

## 2. 해결 내역 및 주요 기능 구현

### 2.1 인메모리 & DB 진행률 추적기 (`progress_tracker.py`, `models/video.py`)
- `Video` 모델에 `progress_percent` (Float, 0.0~100.0) 컬럼 추가.
  - `QUEUED`: `0.0%`
  - `PROCESSING`: 실시간 계산값 (`1.0% ~ 99.0%`)
  - `COMPLETED`: `100.0%`
  - `FAILED`: `0.0%`
- 스레드 안전 싱글톤 `ProgressTracker`를 구축하여 인코딩 진행률이 역행하지 않는 단조 증가(monotonic increase)와 0~100 클램핑을 보장.

### 2.2 FFmpeg 실시간 진행 시간 파싱 (`ffmpeg_service.py`)
- FFmpeg 명령어에 `-progress pipe:1` 옵션을 추가하고, 표준 출력을 라인 단위로 비동기 파싱.
- `out_time_us`를 추출하여 총 영상 재생시간(`duration`) 대비 정확한 진행률 산출:
  - 사전 분석(Probe): `5%`
  - MP4 720p H.264 인코딩: `10% ~ 85%`
  - HLS 세그먼테이션: `86% ~ 98%`
  - 최종 완료: `100%`

### 2.3 REST API 진행률 제공 (`api/v1/videos.py`, `vdstream-api.md`)
- `GET /api/v1/videos/{video_id}/status`:
  ```json
  {
    "status": "success",
    "data": {
      "video_id": "vid_...",
      "status": "PROCESSING",
      "status_message": "720p H.264 인코딩 중 (45%)",
      "progress_percent": 45.0,
      "is_ready": false
    }
  }
  ```
- `GET /api/v1/videos` 목록 조회 시에도 각 항목에 `progress_percent`가 실시간으로 포함됨.

### 2.4 웹 대시보드 실시간 반응형 UI (`index.html`, `dashboard.js`)
- **프로그레스 바 렌더링**: '진행 상태' 열에 Bootstrap 프로그레스 바 및 실시간 `%` 수치 텍스트 표시.
- **무중단 라이브 폴링 (1.5초 주기)**: 테이블에 `PROCESSING` 또는 `QUEUED` 상태 행이 하나라도 있으면 주기적으로 최신 진행률을 fetch하여 DOM의 프로그레스 바 너비를 부드럽게 증가시킴.
- **매끄러운 완료 전환**: 100% 완료 시 전체 페이지 새로고침(`location.reload()`) 없이 녹색 `[완료 (스트리밍 가능)]` 배지와 `[재생]`, `[링크]` 액션 버튼으로 즉시 교체.
